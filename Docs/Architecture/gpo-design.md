# Group Policy Design

This document describes the Group Policy design used in the `corp.ethetic.com` Active Directory security lab.

## Objectives

The GPO design is intended to:

- Apply consistent workstation security settings
- Enforce password and account-lockout controls
- Standardize user access to shared resources
- Enable useful Windows security auditing
- Support centralized monitoring through Wazuh
- Deploy and manage Windows LAPS
- Keep policies scoped to the systems that actually require them

## Organizational Scope

The main workstation policy scope is:

```text
OU=Workstations,OU=Computers,OU=Ethetic,DC=corp,DC=ethetic,DC=com
```

Domain-level security and audit policies are linked where domain-wide enforcement is required.

## Implemented GPOs

### 1. Password and Account Lockout Policy

Configured domain password and lockout controls to reduce weak-password and brute-force risk.

Key controls include:

- Password complexity requirements
- Minimum password standards
- Account lockout threshold
- Lockout duration
- Lockout counter reset

This policy was later used during security testing to generate and investigate account-lockout events.

### 2. Workstation Screen Lock

Applied workstation inactivity and screen-lock settings to domain-joined endpoints.

Purpose:

- Reduce risk from unattended unlocked workstations
- Enforce a consistent workstation security baseline

### 3. Mapped Network Drives

Configured Group Policy Preferences to map shared file resources for domain users.

Examples include departmental and company shares hosted on `FILE01`.

Purpose:

- Provide consistent access to shared resources
- Reduce manual workstation configuration
- Centralize drive mapping management

### 4. Windows LAPS

GPO:

```text
Workstation - Windows LAPS
```

Linked to:

```text
Ethetic
└── Computers
    └── Workstations
```

Configured settings include:

- Backup directory: Active Directory
- Managed local administrator account: `LabLocalAdmin`
- Password complexity and length
- Password rotation
- Password encryption
- Authorized password decryptors

Authorized password readers are controlled through:

```text
LAPS Password Readers
```

This design ensures managed workstations receive unique local administrator passwords instead of sharing one reusable credential.

### 5. Advanced Audit Policy

GPO:

```text
Security - Advanced Audit Policy
```

Configured to use advanced audit subcategories instead of legacy category settings.

Enabled auditing includes:

#### Logon / Logoff

- Audit Logon — Success and Failure
- Audit Account Lockout — Failure
- Audit Special Logon — Success

#### Account Management

- Audit User Account Management — Success and Failure
- Audit Security Group Management — Success and Failure

#### Account Logon

- Audit Credential Validation — Success and Failure
- Audit Kerberos Authentication Service — Success and Failure
- Audit Kerberos Service Ticket Operations — Success and Failure

#### Detailed Tracking

- Audit Process Creation — Success

#### Policy Change

- Audit Audit Policy Change — Success and Failure
- Audit Authentication Policy Change — Success and Failure
- Audit Authorization Policy Change — Success and Failure

The following policy was also enabled:

```text
Audit: Force audit policy subcategory settings
(Windows Vista or later) to override audit policy category settings
```

### 6. Process Command-Line Auditing

Enabled:

```text
Computer Configuration
→ Administrative Templates
→ System
→ Audit Process Creation
→ Include command line in process creation events
```

Purpose:

- Add command-line context to process creation events
- Improve investigation quality for Event ID 4688

## Validation

Policies were validated through a combination of:

- `gpupdate /force`
- Group Policy Results
- Event Viewer
- Wazuh ingestion
- Controlled security testing

Examples of validated outcomes include:

- Event 4688 generated by launching Notepad
- Failed logons visible as Event 4625
- Account lockouts visible as Event 4740
- Security group membership changes visible as Event 4728
- Privileged logons visible as Event 4672
- Kerberos service-ticket activity visible as Event 4769

## Design Principles

The GPO structure follows several basic principles:

- Apply workstation-specific settings at the workstation OU
- Keep domain-wide security controls at the domain level
- Avoid mixing unrelated settings into a single oversized GPO
- Make policies easy to identify by purpose
- Test policy application before relying on it for security monitoring
- Prefer centralized policy enforcement over manual endpoint configuration
